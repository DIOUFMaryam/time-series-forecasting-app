# TSF Documentation

## Introduction

**Purpose**:  
This application is designed for time series analysis, data visualization, and forecasting based on user-selected data from Excel files. It allows users to visualize trends, apply predictive models, and generate forecasts with ease.

**Audience**:  
Data analysts, business professionals, and researchers who require insights from time series data.

**Demo data**:  
The app ships with `telecom_kpis_synthetic.xlsx`, a synthetic dataset of eight fictional telecom KPIs (monthly, 2015-2024) generated by `scripts/generate_synthetic_kpis.py`. The KPI descriptions shown in the sidebar tooltips come from `kpi.ods`, which the same script creates.

## Getting Started

### System Requirements
- Python 3.10 (tested; 3.9 to 3.11 should work, the pinned library versions do not install on newer Pythons)
- Anaconda is the easiest way to get it on Windows
- PyShiny 1.x, Statsmodels, Prophet, Tensorflow
- Pandas, Numpy, Plotly, Arch
- Everything is listed in `app/requirements.txt`

### Installation
1. Get the project folder (clone the repository or unzip it).
2. Open **Anaconda Prompt** (a terminal, not the Spyder console) and create a dedicated environment:
    ```bash
    conda create -n tsf python=3.10
    conda activate tsf
    ```
    If a `tsf` environment already exists from an older version of the app, choose another name (e.g. `tsf-shiny1`).
3. Go to the app directory and install the dependencies:
    ```bash
    cd path\to\TSF\app
    pip install -r requirements.txt
    ```

### Running the App
- From the `app` folder, with the environment active, run:
```bash
shiny run myapp.py
```
- `python myapp.py` also works (it is the command to use from Spyder).
- Wait a little on the first start, then open the local address : ```http://127.0.0.1:8000```
- Press `Ctrl+C` in the terminal to stop the app. Next time, only `conda activate tsf` and `shiny run myapp.py` are needed.
- On the public demo, saving model parameters and editing this documentation are turned off (read-only mode), so every visitor sees the same version.
- **From Spyder**: install `spyder-kernels` in the environment, select the environment's `python.exe` under *Tools → Preferences → Python interpreter*, restart the console and run `myapp.py`. Stop the app by interrupting or restarting the console.

## User interface
### Overview 
![image.png](images/app.png)

The app is divided into tabs located on the sidebar and their layouts shown in the main page. 
First, the user selects an Excel file among those available in the directory and then he can choose the variable (KPI) to analyze. After that, he switches between tabs to visualize results.

### Navigation 
There are five tabs :

1. *Time Series Plot* : graphs of the selected time series, the moving average and the moving std. 
2. *Data* : shows the selected time series table (tail) and exploratory data analysis for time series (mean, min, max, median, time range, stationarity tests, trend, seasonality, etc).
3. *Model* : allows user to visualize model predictions and performance.
4. *Forecast* : in this tab, users can see the graphs and table of the predictions with the download option.
5. *Documentation* : this tab explains how the app works, its purpose and its contents.

---

## Functionality
- **Choose Excel File**: there is a files directory where is stored excel files, containing the time series. The app allows users to select which file to upload and analyze. The file is expected to have a *.xlsx* extension, dates in the first column (one row per month) and one numeric column per KPI.
- **Select Column**: if the selected file has multipe time series (columns), the user can choose which one to analyze. Rigtht under this section, there is an information icon that briefly describes the selected variable when hovered on (descriptions are read from `kpi.ods`; KPIs without one show a generic message).
- **Time Series Plot**: this tab contains two graphs, a simple plot of the time series and another plot of the scaled time series, moving average and moving std. The first plot allows the user to do a visual inspection of the time series, maybe detect trend and seasonality if they are not too subtile to the naked eye. The plot of the moving average and the moving std has the goal to visually determine whether the series is stationary. Indeed, if they are parallel to the x-axis, it means the series is stationary. And of course scaling the data helps see the lines clearly and avoid any confusion. 
- **Data**: in this tab, the user can have an overview of the data and its description (time range, mean, min, max, median, etc). For the median, the date shown is that of the closest observation, since the median of an even number of points is usually not one of the values. The goal is model selection,  gathering all the information needed to determine the right model for the series, starting with stationarity tests (DF-GLS, a variant of ADF, plus PP and KPSS). Then we get data volume, seasonality, trend and missing values. All this leads to the recommended model.
- **Model**: users can choose between three models : SARIMA, Prophet and LSTM and the trainng begins automatically. Then a graph of the time series (actual values) and the predicted values is shown, allowing users to visually evaluate the accuracy of the model. Users can also choose the future predictions time (eg 12 months) or the model parameters. The data is by default trained on set parameters, but if the user isn't satisfied he can try different parameters and save them for future use if happy with them. The *Choose model parameters* and *Use saved parameters* options are mutually exclusive: ticking one unticks the other. When no parameters have been saved for a KPI, *Use saved parameters* falls back to the defaults and says so. To be sure of his choice, he can check the model performance (error (mse, mae, mape, etc) and accuracy, homoscedasticity and autocorrelation between residuals). 
- **Forecast**: this tab shows the generated predictions of the selected time series by all the models and their accuracy, so as to see the most accurate model. There is also a plot of the predictions to compare and determine the most optimistic (pessimistic) model. Then users can choose which variables (the columns of the loaded file) to generate predictions from and the right model for each and click on the *Download* button to save the predictions in an Excel file or just click on *Show forecast* to visualize them within the app. If the LSTM model is unavailable on the machine (see Troubleshooting), it is shown as "unavailable" and the most accurate model is chosen among SARIMA and Prophet.
- **Documentation**: provides in-app documentation for user assistance.

## Troubleshooting
- **Common Issues**:
    - *pandas fails to build / `No module named 'pkg_resources'`*: the Python version is too new. Use a Python 3.10 environment.
    - *pip reports `ResolutionImpossible` between `typing_extensions` and tensorflow*: an older `requirements.txt` is being used. The current one pins `tensorflow==2.14.1`, which installs alongside Shiny 1.x.
    - *`cannot import name 'TypeIs' from 'typing_extensions'`*: reinstall with the provided `requirements.txt` (it requires `typing_extensions>=4.10`).
    - *`DLL load failed ... Une stratégie de contrôle d'application a bloqué ce fichier`*: Windows Smart App Control blocked a TensorFlow file. The app still starts, SARIMA and Prophet work, and the LSTM model shows as unavailable. To use LSTM, run the app under WSL or on a Linux machine, or turn Smart App Control off (on many Windows versions it cannot be turned back on afterwards).
    - *`invalid command name ".!canvas"` in the Model tab*: matplotlib was using a desktop window backend. This is fixed in the code (`Agg` backend).
    - *`'Prophet' object has no attribute 'stan_backend'`*: run `pip install cmdstanpy==1.1.0`.
    - *The app seems slow at startup or the LSTM tab is slow*: normal. Prophet takes a while to load, TensorFlow loads the first time LSTM is used, and LSTM trains from scratch on each request.
